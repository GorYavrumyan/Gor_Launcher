# GorLauncher — изменения

## НОВОЕ: режим Big Picture (ТВ / диван)

Открыть: меню ☰ → «📺 Режим Big Picture» (или F11), либо запуск `bridge_loader.py --bigpicture`
(сразу в режиме, без обычного окна — для автозагрузки на ТВ/HTPC).

| Действие | Геймпад (XInput) | Клавиатура |
|---|---|---|
| Навигация | D-pad / левый стик | стрелки |
| Выбрать / запустить | A | Enter, Пробел |
| Назад (меню выхода) | B | Esc, Backspace |
| В избранное (в «Стриме» — значение назад) | X | F |
| Действия с игрой | Y | Y |
| Раздел назад / вперёд | LB / RB | Shift+Tab / Tab |
| Главное меню | Start | M, F10 |

Разделы: **Библиотека** (строка на группу) · **Избранное** · **Недавние** (из истории) · **Стрим**.
Стрим: хост → приложение (список берётся с хоста через `moonlight list`, при ошибке — стандартный) →
качество (разрешение / FPS / битрейт, запоминается) → запуск Moonlight.
Пока идёт игра или стрим, окно прячется, ввод геймпада игнорируется; по завершении интерфейс возвращается сам.

Файлы: `extras/big_picture.py` (интерфейс), `shared/gamepad.py` (XInput через ctypes, без зависимостей,
логика отделена от железа), `PCStreamManager.list_apps()` / `.last_process` в `remote/moonlight_cantrol.py`,
ключи `big_picture.*` в `lang/ru|en|es.json` (армянский откатывается на русский).

### Подключение ТВ (Android TV / Moonlight) из лаунчера
Лаунчер — программа для Windows и на Android TV не запускается. Работает так: ПК крутит лаунчер в режиме
Big Picture, Sunshine транслирует экран, Moonlight на ТВ показывает его и передаёт геймпад. Всё настраивается
из лаунчера: меню ☰ → «📺 ПОДКЛЮЧИТЬ ТВ» (окно Sunshine, вкладка «ТВ»):
1. **Вход в Sunshine** — логин/пароль веб-интерфейса (можно «запомнить» или «создать логин автоматически»).
2. **Приложение «GorLauncher Big Picture»** — добавляется в Sunshine без перезапуска (через REST API; если API
   недоступно — запись в `apps.json`). Запускает `bridge_loader.py --bigpicture`.
3. **Сопряжение ТВ** — PIN из Moonlight вводится здесь (раньше — только на веб-странице Sunshine); показан IP ПК.
4. **Подключённые устройства** — список и отключение.
Файлы: `remote/sunshine_api.py` (клиент API без Qt), `remote/tv_setup.py` (вкладка), `shared/single_instance.py`.

**Защита от двойного запуска.** Если лаунчер уже открыт, повторный запуск не создаёт вторую копию (обе писали
бы в один `games_data.json`): обычный запуск просто показывает основное окно, а `--bigpicture` (из Sunshine)
открывает Big Picture в работающем экземпляре и остаётся жить, пока режим открыт — стрим живёт, пока жив процесс,
запущенный Sunshine. Перезапуск лаунчера (смена языка/аккаунта) обходит проверку флагом `--new-instance`.

Исправлено: синхронизация игр со Sunshine удаляла приложения, добавленные вручную (оставляла только «Desktop» и
«Steam Big Picture») — теперь сохраняются и «GorLauncher…»; окно Sunshine искало папку `Sunshine/` относительно
текущей папки процесса (теперь — от корня проекта); `version.json` читался относительно текущей папки.

Проверено: клиент API (22) и вкладка (11) — против поддельного HTTPS-сервера с Basic-авторизацией и теми же
эндпоинтами; повторный запуск — на реальных процессах. НЕ проверено на настоящем Sunshine/Android TV/Windows:
имена эндпоинтов и поля (`/api/pin`, `/api/clients/*`, `/api/apps` с `index`) взяты из документации Sunshine,
формат может отличаться в вашей версии (при неудаче вкладка откатывается на правку `apps.json`).

### Оформление Big Picture = оформление лаунчера
Big Picture не имеет своей «темы» — он берёт всё от обычного режима:
- **Цвета** — из активной темы (`themes.colors()`: Theme Studio и личные правки); цвета, которые на расстоянии
  дивана сливаются с фоном, подтягиваются до читаемого контраста (текст ≥ 3:1, приглушённый ≥ 4.5:1).
- **Фон и эффекты** — зеркалятся те же слои `api.design` (обои, анимированный градиент, звёзды/снег и т.д.),
  что аддоны добавили в обычное окно, поверх содержимого, как и в лаунчере.
- **Карточки, вкладки, заголовки групп, плашка статистики** — те же виджеты с теми же `objectName`
  (`GameCard`, `GameCardImage`, `GameCardName`, `GameCardTime`, `RunGameBtn`, `GroupToggleBtn`, `GroupTitleLabel`,
  `StatsLabel`, `QTabBar`), поэтому тема и QSS применяются сами: красная рамка запущенной игры, золотая — избранного,
  стеклянные карточки от аддонов (стиль окна лаунчера наследуется) и т.д.
- **Шрифт** — тот, что использует лаунчер сейчас. **Язык** — тот же; добавлены армянские строки (hy; просьба
  проверить перевод носителем), подписи вкладок/статистики/карточек берутся из ключей обычного режима.
- Размер обложки уменьшен (0.78), тексты и кнопка — крупные, для ТВ.

Найдено при отладке: «голый» `setStyleSheet("background: transparent;")` на контейнере каскадом перебивает тему
у ВСЕХ потомков (в Qt стиль родителя приоритетнее стиля приложения независимо от специфичности) — в Big Picture
прозрачность контейнеров задана правилами по `objectName`.

Проверено: 31 сценарий интерфейса с подставным геймпадом/Moonlight, 9 сценариев на реальном `GORLauncher`
(запуск игры через режим, возврат, запись времени, выход), запасной путь запуска без карточки, дымовой запуск
`--bigpicture`. НЕ проверено: реальный геймпад и реальный Moonlight/Sunshine, Windows, телевизор.
Формат вывода `moonlight list` нигде не гарантирован — разбор терпимый, при пустом результате показываются
«Desktop» и «Steam Big Picture».

Попутно найдено и исправлено: `launch_game_from_wheel` искал карточку по «id ИЛИ имя» и при одинаковых названиях
запускал не ту игру (затрагивало и колесо фортуны); запуск без видимой карточки шёл через голый `os.startfile`
(без рабочей папки, аргументов и учёта времени) — теперь через ту же карточку-невидимку.

## Исправления (ревизия кода)

Проверено запуском: компиляция 79 файлов, импорт 44 модулей, pyflakes/pylint, интеграционные тесты
реального `GORLauncher` (офскрин), тесты safe_json, account_manager, drop в группах, редактора игр,
LAN-broadcast, adblock, дымовой запуск `bridge_loader.py --account X`.
НЕ проверялось на Windows (tasklist, junction, taskkill) — только чтением кода.

## Потеря данных
1. `GORLauncher.save_data()` затирал блок `browser` (закладки/история/настройки) устаревшей копией → теперь берёт актуальный блок с диска.
2. Запись JSON «вслепую» (обрезание файла при ошибке сериализации; при битом файле создавалась пустая база и затирала всё) → новый `shared/safe_json.py`: сериализация до записи, `.bak`, `.corrupt-*`; запись на месте (hardlink на файл аккаунта сохраняется). Применено в лаунчере, редакторах, lang_loader, браузере, account_manager, ControlCenter, настройках аддонов.
3. Имя аккаунта `..`/`.` → `delete_account` делал rmtree корня проекта; `Vova`/`vova` делили папку → валидация имён, проверка пути, регистронезависимая уникальность.
4. `_link_file/_link_dir` молча удаляли реальные данные → синхронизация/`.orphan-*`/`.bak-*`.
5. Редактор игры стирал `guide_group_id`, `wiki_url` и пр., откатывал время игры → работает со свежим файлом и сохраняет лишние поля.
6. `browser_widget.save_data`/`_write_now_playing`/`set_language`: при нечитаемом файле больше не пишут почти пустой словарь поверх библиотеки.

## Логика
7. «Редактировать» на играх без группы и из «Избранного» открывало пустую форму → поиск по id во всех списках.
8. Удаление/перенос/учёт времени сопоставляли «id ИЛИ имя» → строго по id (`_find_game_ref`); удаление из «Избранного» работает.
9. Конец игровой сессии терялся при пересоздании карточек (`refresh_list`) → обработчик в лаунчере (`track_game_monitor`/`on_session_finished`), потоки не собираются GC; при выходе фиксируется время и потоки останавливаются.
10. `ProcessMonitor`: точное сравнение имени процесса (не подстрока), остановка потока, паузы не входят в время игры.
11. Drag-and-drop между группами (`dragEnterEvent/dropEvent`) восстановлен; порог начала drag.
12. Windows: аргументы запуска (`shlex` съедал `\`).
13. Колесо фортуны не останавливает уже запущенную игру.
14. Шрифт веб-страниц (Qt6: `globalSettings()` не существует) → через `profile.settings()`.
15. Апдейтер: добавлены `addon_API` и `GOR_Brauzer` (кроме `GOR_Profile`, `_data`, `__pycache__`); отмена — по флагу, а не по тексту.
16. Экспортёр: недопустимые символы в именах, падение потока без сигнала, блок `browser` не экспортируется.
17. ControlCenter: не теряет аддоны, которые он не показывает; не пишет файл при ошибке чтения.
18. `cover_ipc.try_decode_line` зависал на пустой/битой строке; запрос обложки кодируется в URL.
19. Трей: `quitOnLastWindowClosed` на время скрытия окна, явный выход в `closeEvent`.
20. Запуск из другой папки (`cwd`, `version.json`).

## Браузер / безопасность
21. Adblock: перебор всего набора доменов на каждый запрос (сотни тысяч) → O(меток), 2000 проверок — 2 мс; гонка «Set changed size».
22. LAN broadcast: пакеты недоверенные → только http(s), лимиты, дедупликация (loopback дублировал), закладки чанками (раньше терялись при больших списках), в тосте видны реальные хосты.
23. Синхронизация буфера: эхо между ПК и утечка пароля из менеджера паролей в сеть.
24. VOT-скрипт внедрялся на все сайты → только на сайты из `VOT_URL_PATTERNS`.
25. Приватный профиль получает блокировщик рекламы; порт broadcast валидируется; защита от спама `window.open`.
26. Хранилище паролей: fsync + `.bak`, очистка буфера обмена через 30 с.
27. Прочее: `-0.0 MB` в загрузках, потокобезопасность watchdog/logger, `Settings.set` откатывается при ошибке, `themes.delete/import` защищены от rmtree вне папки тем, `system.idle_seconds` (переполнение GetTickCount), `kill()`, `fuzzy_score(None)`, `Collection.find` на несравнимых типах, `SystemExit` из аддона, Sunshine (статус в потоке, `pkill -x`), PIN Moonlight через `secrets`.

## Поведение, которое изменилось намеренно
- Апдейтер теперь обновляет `addon_API/` и `GOR_Brauzer/` — если в репозитории они старее локальных, не принимайте эту правку.
- Экспорт архива больше не включает блок `browser` из `games_data.json`.
- Имена аккаунтов и групп ограничены (см. п. 3).
